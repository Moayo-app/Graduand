# graduand verifier module (pre-public)

판정기 넷(`refs` · `ui-paths` · `shared-values` · `shared-values-cross`)과 판정 스키마 하나,
값 어댑터(`css-custom-properties` — Tailwind v4 `@theme` 포함), fragment codec, CLI.
고객 CI 와 브라우저 진단 페이지가 **같은 모듈**을 import 한다 — 사본이 없다.

- 런타임 의존성 **0**. 개발에 빌드 단계 없음 — Node ≥23.6 이 타입을 지우며 소스가 그대로
  돈다(`node src/cli.ts`). ⚠️ **발행본은 다르다** — `npm run build` 가 `dist/` 로 내고
  `bin`·`exports` 가 그 산출물을 가리킨다: 발행본은 남의 기계에서 도는데, 그쪽 번들러와
  Node 가 `node_modules` 안의 `.ts` 를 받아 준다는 것은 **우리가 검증할 수 없는 선언**이다.
- 수는 3상태(통과 · 위반 · 미판정 + 사유 코드)로만 말한다. 점수·등급·백분율 API 는 없다.
- ⭐ **측정 봉투가 격자와 시야를 든다**(개정 3) — 격자는 선언 바이트와 판정 결과를 **둘 다**
  쥔 쪽만 셀 수 있어서, 세는 것은 저장소를 읽은 표면이고 요약을 받은 쪽은 **받아 그린다**
  (세는 손은 여전히 `admissionGrid` 하나다). ⛔ `Judgment` 에는 싣지 않는다 — 바이트
  동일성 약속이 거기 걸려 있고, 격자와 시야는 **측정의 속성**이지 판정이 아니다.
- ⭐⭐ **선언 0 에서도 보이는 사실이 봉투에 탄다**(개정 5 · `undeclared.ts`) — 선언하지 않은
  저장소에서 축이 미판정인 것은 옳지만, 그 보고가 네 칸 중 **하나**만 재어진 화면이라
  읽는 사람의 「할 말이 거의 없다」도 틀리지 않았다. ⇒ 사실을 적는다: **문서 사본**
  (같은 블록이 문서 둘 이상에 축자로 산다 — `.md` 본문은 이미 실려 있어 요청이 0 건 늘지
  않는다) · ⭐ **갈라진 사본**(겹친 줄이 어느 쪽의 고유한 줄보다도 많되 축자로 같지는 않은
  쌍 — 개정 6)
  · **선언할 수 있는 분모**(어댑터마다 그 꼴의 경로 수 · 본문이 실린 수).
  ⚠️ **사본의 칸이 둘인 것이 요점이다** — 앞은 「아직 같다」이고 뒤는 「이미 두 말을 한다」:
  갈라진 쪽을 보지 못하던 동안 사본 둘 중 하나만 고쳐진 저장소의 수가 **0 건**이었고, 그
  0 은 「사본 없음」으로 읽혔다. ⛔ 유사도 점수는 생기지 않았다 — 단위는 **축자 동일한 줄**
  이고 내는 것은 수 둘(겹친 줄 · 갈라진 줄)이다.
  ⭐ **단위는 쌍이고, 보고 표면은 가족으로 접어 그린다**(`foldDiverged`) — 집이 N 이면 쌍이
  C(N,2) 로 불어 같은 손잡이가 열 몇 번 반복된다(실측). ⛔ 봉투는 쌍을 그대로 나른다:
  접는 것은 **파생**이라 스키마가 움직이지 않고, 접는 손은 측정 명령과 페이지가 **같은 하나**다.
  ⛔ **판정기를 늘리지 않았다** — 선언 없이 위반을 짓는 축은 우리가 지은 규율이고 그것은
  이 모듈이 파는 명제의 반대다: 상태도 사유 코드도 3상태의 수도 늘지 않았고, 이 칸에서
  통과나 위반을 읽을 수 있는 필드가 **하나도 없다**(그 부재를 테스트가 전수한다).
- 네트워크는 `api.github.com` 하나(브라우저 로더)뿐이고, 결과를 되쏘는 경로는 없다.
- ⭐⭐ **헌법이 여럿이다**(개정 4) — 선언이 공유값 축을 **이름으로** 여럿 들고
  (`shared-values.<축>`, 이름은 **고객이 짓는다**), 판정의 칸은 축마다 둘이다
  (`shared-values:<축>` · `shared-values-cross:<축>`). ⭐ **축마다 정본이 따로 선다** — 한
  저장소가 디자인 정본과 API 정본에 동시에 답하고, 그 둘이 **다른 상류**에 살아도 한 선언이
  둘을 가리킨다(저장소가 여럿이고 규율이 갈래로 파편화된 조직이 그 모양이다). ⛔ 축 사이를
  접는 산술은 없다 — 한 축의 위반이 다른 축의 통과를 가리지도, 그 반대도 아니다. 고객이
  **편입에 적는 것은 등록부의 이름 하나**이고(`shared-values`), 그 이름이 축 전부의 칸을
  모은다(`isCheckOf` — 모으는 술어는 하나다).
- 공유값의 교차 축(박제 == 정본)은 그 축의 정본 포인터(`canon`)를 따라 **다른
  체크아웃**의 정본을 읽어 판정한다 — 분모는 정본이 든 토큰이고, 박제에서 조용히 빠진
  토큰은 **위반**이다. 체크아웃이 하나뿐인 표면에서는 그 칸이 **「판정 불가」로 정직하게**
  적힌다(`single-repo-surface`) — 칸을 비우면 「위반 0」으로 읽히기 때문이다.
- 공유값 증거는 좌표(토큰 · 파일 · 행 · 사유)뿐이다 — 고객 파일의 값·산문은 보고에 싣지 않는다.
- **헌법 조립**(`canon` · `link`)은 선언을 **짓는** 쪽이다 — 「헌법을 만든다」의 둘(규범 저작
  1회 · 편입 저장소마다) 중 첫째이고, `init` 의 빈 스캐폴드가 둘째다. `canon` 은 「이 저장소가
  정본이다」를 적고(박제 0 · 포인터 0), `link` 는 「정본은 저기이고 값은 이것이다」를 적는다.
  ⭐⭐ **박제 값은 손으로 받지 않고 정본에서 읽는다** — 저장소 N 개에 같은 값을 손으로 옮기는
  행위가 바로 이 모듈이 재는 갈라짐의 생산 공정이다. ⛔ 해석되지 않는 정본 값(`var()` 간접 ·
  중복 정의)은 **박제하지 않고 말한다**: 기준이 거짓이면 그 위의 모든 수가 거짓이다.
  ⛔ 덮어쓰지 않는다 — 선언이 있으면 **쓰지 않고** 조립한 것을 stdout 으로 낸다. ⭐ 다만 그
  바이트는 「당신의 선언 + 축 하나」의 **전문**이다(`--axis` 가 그 이름이다): 디자인 헌법을
  선언한 저장소가 API 헌법을 더하는 것이 개정 4 의 평상시이고, 옮길 칸을 고객이 고르게 두면
  두 선언을 손으로 합치는 그 공정이 남는다. ⛔ **같은 이름의 축은 거부한다** — 있는 축을 다시
  짓는 것은 고객이 적은 박제와 갈라짐 선언을 지우는 일이다. ⛔ git 을 건드리지 않는다.
  ⭐ 조립기는 **브라우저에서 그대로 돈다**(`composeConstitution`) — 화면이 내보내고 CLI 가 쓴다.
- **하류 배달**(`deliver`)은 **축마다** 나른다 — 축의 정본에서 읽어 그 축의 박제 칸만 바이트로
  고치고, 박제가 없는 축(그 축의 정본 자신)이나 정본이 시야에 없는 축은 **이름과 사유로 남는다**
  (축 하나가 서지 못한다고 다른 축의 배달이 틀려지지 않는다). ⭐ 같은 토큰을 두 축이 박제해도
  서로의 칸을 고치지 않는다 — 치환의 창이 **그 축의 구간**이다.
- **하류 배달**(`deliver`)은 교차 축이 **판정만** 하던 자리에서 값을 다시 쓰는 손이다 —
  정본에서 읽어 **하류의 박제 칸**을 맞춘다. ⭐⭐ **분모는 받는 쪽 선언이다**(작업장 배달의
  allowlist 와 같은 성질): 하류가 **박제한 토큰만** 나른다. 건드리지 않는 자리 셋 —
  선언된 갈라짐(사유를 달아 **기준을 옮긴** 자리) · 하류가 박제하지 않은 정본 토큰(분모를
  넓히는 것은 받는 쪽의 선언 행위이고, 그 자리는 **판정**이 위반으로 센다) · 정본이 모르는
  박제(저장소 고유값). ⛔ **다시 직렬화하지 않는다** — 선언의 다른 칸은 바이트로 그대로고,
  배달의 diff 는 나른 값의 줄들이다. ⛔ 빨강을 내지 않는다(빨강의 근거는 판정의 몫이다) ·
  git 0. ⚠️ 배달이 고치는 것은 **선언**이라, 코드가 아직 안 따라왔으면 CI 축(코드 == 박제)이
  그 다음에 **코드를 가리킨다** — 그것이 고객이 할 일이고 배달이 대신 삼키지 않는다.
- 편입 격자(규칙 × 표면)는 선언에서 **파생**된다 — 분모도 칸 수도 고객이 적는 자리가 없고,
  보고는 「관할 N — 위반 k · 통과 p · 미판정 m」으로만 말한다.
- **분모를 묻는 쪽**(`rules`)은 선언이 **무엇을 분모로 세웠는가**만 낸다 — 편입된 규칙과 그
  규칙이 고른 판정기 · 공유값 **축마다의 정본 주소** · 면제와 그 만기 · 관할의 모양.
  ⭐ 개정 4 가 만든 「한 저장소가 헌법 여럿에 답한다」가 사람 눈에 서는 자리다(판정은 정본을
  **읽고** 비교하지만 어디서 읽었는지를 적지 않는다). ⛔ **판정하지 않는다** — 그 산출에
  `pass`·`violation` 이 없고 빨강도 없다(0 아니면 2): 상태는 판정의 산출이고 분모는 선언의
  산출이라, 한 화면에 섞으면 「선언했다」가 「통과했다」로 읽힌다. ⛔ **시계가 없다** — 만기의
  날짜는 적지만 「넘겼는가」는 적지 않는다: 적으면 같은 선언이 날마다 다른 바이트를 내고,
  넘김을 판정하는 손이 봉투(`expiry.ts`) 밖에 하나 더 생긴다. ⭐ 그래서 `--json` 의 바이트가
  **같은 선언에서 같다** — 에이전트가 그 산출을 diff 로 쥘 수 있는 근거다(수를 세는 손은
  여전히 `grid.ts` 하나다: `admissionShape` 가 분모를 읽고 `admissionGrid` 가 상태를 얹는다).
- **고객 CI 의 입구**는 [`ci/`](ci/) 가 갖는다 — GitHub 재사용 Action(`ci/action.yml`) ·
  GitLab include(`ci/gitlab-ci.yml`) · 빅버킷 조각(`ci/bitbucket-pipelines.yml`).
  ⚠️ **셋째만 사본이 된다** — 빅버킷 Pipelines 에 원격 include 가 없어 고객이 붙여 넣는다:
  그래서 그 조각이 드는 것은 부트스트랩 clone 과 공유 스크립트를 부르는 줄뿐이고, 없앨 수
  없는 그 사본은 **선언하고 가드를 세웠다**(테스트가 clone 하는 입구 전수를 함께 문다).
  ⭐⭐ **변환의 손은 둘이다**(`ci/graduand-ci.sh` 가 argv · `ci/graduand-peers.sh` 가 시야):
  입구가 셋인데 「루트 목록 → `--root` 반복」을 각자 적으면 그 사본들은 갈라지고, 갈라진
  뒤에도 양쪽이 자기 기준으로는 옳다 — 이 모듈이 재는 그 결함이다. ⭐ **체크아웃 N 개를 받는
  모양이 요점**이고(교차 축이 설 수 있는 유일한 표면), 조립을 고객에게 맡기면 가장 중요한
  판정이 가장 어려운 호출이 된다. ⛔ 종료 코드를 접지 않는다 · 토큰 0 · 다른 Action 0 ·
  Node 를 세우지 않고 **먼저 묻고 멈춘다**(≥23.6 · exit 2 — 돌 수 없는 것은 초록이 아니다).
  ⚠️ 이 폴더는 **발행본에 실리지 않는다**(`package.json` 의 `files` 가 `dist`·README·증서
  셋이다) — 저장소 참조(`owner/repo/path@ref`)로 쓰이는 산출이고 npm 소비자가 받을 것이 아니다.

```
npm test          # node --test (발행본을 실제로 포장해 푸는 AC 포함)
npm run typecheck # tsc --noEmit
npm run build     # tsc → dist/ (발행본의 산출 — prepack 이 같은 것을 돌린다)
node src/cli.ts [--root <path>]... [--json | --fragment]
node src/cli.ts init [--root <path>]
node src/cli.ts canon --axis <name> --adapter <id> --file <path>... --scope <scope> [--root <path>]
node src/cli.ts link --axis <name> --canon <owner/name> --canon-file <path> --canon-scope <scope> \
                     [--adapter <id> --file <path>... --scope <scope>] [--root <path>]...
node src/cli.ts deliver [--root <path>]...
node src/cli.ts rules [--root <path>]... [--json]
node src/cli.ts --help
```

`--root` 를 여러 번 주면 **한 잡에 체크아웃 N개**다 — 교차 축이 설 수 있는 유일한 표면이고,
각 체크아웃은 나머지 전부를 시야로 판정된다. 보고는 체크아웃마다 한 절 + 관할 합산 한 줄이다.

⚠️ 이 폴더는 공개 배달 저장소([Moayo-app/Graduand](https://github.com/Moayo-app/Graduand))로
옮겨질 범위다 — **공개-안전만 담는다.** 패키지명 `graduand` 는 **확정됐다**(이름 트랙의
선행조건이 전부 닫혔다). ⛔ **그래도 `private: true` 는 남는다** — 그것을 걷는 조건은 이름이
아니라 **코드 이사와 공개 전환**이다(아래). ⚠️ 상표 심사가 진행 중이라 이름이 다시 열릴 수
있는 축이 하나 남아 있다.

⭕ **`private` 를 걷는 시점은 하나다** — 코드 이사와 **공개 전환** 뒤다. ⛔ 지금 걷지 않는다:
걷는 순간 이 모듈은 발행 가능해지고, 발행된 판은 되돌릴 수 없다(npm 은 취소된 버전
문자열까지 영구히 막는다). 그래서 `private` 가 걷히는 PR 은 **그 둘이 끝났음을 본문으로
밝힌다** — 그 짝으로, 걷히지 않은 동안 `private: true` 가 서 있는지를 `src/package.test.ts`
가 문다. ⭐ 장기 경로는 Trusted Publishing(GitHub Actions OIDC + provenance)이고 **공개
저장소가 전제**라, 고객이 「이 모듈이 그 저장소 그 커밋에서 나왔다」를 **검증**하게 된다 —
이 제품이 파는 명제를 자기 배포에 적용하는 자리다.
